2. DATABASE SCHEMA & PERSISTENCE
--------------------------------
* Set up SQLite persistence storage on the Flask backend (`backend/roadsense.db`) with schemas mapping:
  - `users`: Stores authenticated usernames, passwords, device hardware fingerprints, and dynamic friendly names.
  - `reports`: Tracks logged shocks containing GPS coordinates, speed, computed vertical SVM variance, raw 3-axis accelerometer/gyro scope JSON waveforms, and vehicle class labels.
  - `active_riders`: Logs live tracking coordinate ticks, speed, vehicle classification, and computed suspension health percentages.
* Set up SQLite local buffering on the Expo client using `expo-sqlite` to buffer sensor telemetry locally when offline and queue them for server syncing.

3. ADVANCED DIGITAL SIGNAL PROCESSING (DSP) & STATE ESTIMATION
--------------------------------------------------------------
* Orientation Compensated Decomposition: Implemented low-pass filters (98% coefficient weight) tracking the gravity vector to extract true vertical acceleration and horizontal dynamic forces, independent of device tilt or placement.
* Sigmoid Logistic Classifier: Implemented RMS (Root Mean Square), Peak Amplitude, and ZCR (Zero Crossing Rate) feature extraction to filter out transient phone handling drops from true road anomalies.
* Latency Compensated GPS Projection: Multiplied device speed by GPS latency duration (0.8s lag window) to shift recorded coordinates backward along the vehicle's heading vector for spot-on hazard mapping.
* DBSCAN Spatial Aggregation: Formed verified pothole clusters using DBSCAN, weighting centroids based on vehicle types (prioritizing car suspension shocks over off-road vehicles) and signal strength.
* Bayesian MCMC change-point validation: Runs Markov Chain Monte Carlo calculations to evaluate verification confidence scores (0% to 100%) for clusters.

4. FLASK REST API ENDPOINTS
---------------------------
* Auth: POST `/api/auth/register` and POST `/api/auth/login` to authenticate users and cache JWT tokens.
* Sync: POST `/api/sync` to upload buffered local reports from mobile.
* Real-Time Stream: GET `/api/stream` SSE stream pushing real-time synchronization alerts and rider tracking movements.
* Live Tracking: POST `/api/location` and GET `/api/locations` to push and fetch live rider coordinates.
* Stats & Board: GET `/api/stats`, GET `/api/potholes`, and GET `/api/leaderboard` to fetch dashboard records.
* DB Reset: POST `/api/reset` to refresh the dataset for debugging.
